# EventBus

`EventBus` — глобальная типизированная шина уведомлений. Отправитель сообщает о произошедшем событии всем подписчикам и не получает от них управляющий результат.

## Когда использовать

`EventBus` подходит для реакции на уже произошедший факт:

- обновление UI;
- звук и визуальные эффекты;
- аналитика и достижения;
- уведомление независимых подсистем;
- события жизненного цикла SDK.

Если обработчик должен изменить параметры, заменить результат или запретить исходное действие, используйте [HookSystem](../../HookSystem/README.md).

| EventBus | HookSystem |
| --- | --- |
| Уведомляет о событии | Перехватывает действие |
| Не возвращает решение отправителю | Может изменить или заблокировать действие |
| Обработчики независимы | Обработчики образуют последовательную цепочку |
| Обычно используется после изменения состояния | Обычно используется до и вокруг действия |

## Объявление события

Интерфейс события должен наследовать `IGlobalSubscriber`:

```csharp
public interface ICoinsChangedEvent : IGlobalSubscriber
{
    void OnCoinsChanged(int amount);
}
```

Один объект может реализовывать несколько интерфейсов событий.

## Подписка

```csharp
public sealed class CoinsView : MonoBehaviour, ICoinsChangedEvent
{
    private void OnEnable()
    {
        EventBus.Subscribe(this);
    }

    private void OnDisable()
    {
        EventBus.Unsubscribe(this);
    }

    public void OnCoinsChanged(int amount)
    {
        UpdateView(amount);
    }
}
```

`Subscribe()` автоматически находит все event-интерфейсы объекта. Повторная подписка одного экземпляра не добавляет дубликат и записывает предупреждение.

Компоненты на основе `PRMonoBehaviour` регистрируются в `EventBus` автоматически в рамках lifecycle SDK. Не добавляйте им дополнительную ручную подписку без необходимости.

## Публикация

```csharp
EventBus.RaiseEvent<ICoinsChangedEvent>(
    listener => listener.OnCoinsChanged(currentCoins));
```

Listeners вызываются в порядке подписки. Исключение одного listener логируется и не останавливает вызов остальных.

`RaiseEvent` не предназначен для получения результата или изменения дальнейшего поведения отправителя:

```csharp
// Не используйте EventBus как скрытый запрос разрешения.
EventBus.RaiseEvent<ICanBuyEvent>(listener => listener.Check(context));

// Для управляемого перехвата используйте HookSystem.
HookManager.Instance.Publish(context, BuyItem);
```

## Изменение подписок во время публикации

Публикация выполняется по snapshot списка. Поэтому добавленный во время callback listener начнёт получать события со следующей публикации. Listener, удалённый во время текущей публикации, может завершить уже начатый цикл и гарантированно отсутствует в следующем.

## Диагностика и очистка

Количество подписчиков определённого интерфейса:

```csharp
int count = EventBus.GetSubscriberCount<ICoinsChangedEvent>();
```

Полная очистка:

```csharp
EventBus.Clear();
```

`Clear()` удаляет все глобальные подписки и предназначен для полного reset SDK, тестов или смены изолированного runtime-контекста. Не вызывайте его для очистки одного объекта.

## Ограничения

- Используйте `EventBus` с основного Unity-потока. Коллекции защищены lock частично, но callbacks и создание snapshot выполняются вне него.
- Система хранит сильные ссылки на listeners до `Unsubscribe()` или `Clear()`.
- Забытый `Unsubscribe()` удерживает обычный C#-объект в памяти и может оставлять уничтоженный Unity-объект в списке.
- `EventBus` не гарантирует приоритеты. Если порядок является частью игровой логики, рассмотрите `HookSystem`.
