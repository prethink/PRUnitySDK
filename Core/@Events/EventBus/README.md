# EventBus

`EventBus` — глобальная типизированная шина уведомлений. Отправитель сообщает о произошедшем событии всем подписчикам и не получает от них управляющий результат.

## Когда использовать

`EventBus` подходит для реакции на уже произошедший факт:

- обновление UI;
- звук и визуальные эффекты;
- аналитика и достижения;
- уведомление независимых подсистем;
- события жизненного цикла SDK.

Если обработчик должен изменить параметры, заменить результат или запретить исходное действие, используйте [HookSystem](../../HookSystem/README.md).

| EventBus | HookSystem |
| --- | --- |
| Уведомляет о событии | Перехватывает действие |
| Не возвращает решение отправителю | Может изменить или заблокировать действие |
| Обработчики независимы | Обработчики образуют последовательную цепочку |
| Обычно используется после изменения состояния | Обычно используется до и вокруг действия |

## Объявление события

Интерфейс события должен наследовать `IGlobalSubscriber`:

```csharp
public interface ICoinsChangedEvent : IGlobalSubscriber
{
    void OnCoinsChanged(int amount);
}
```

Один объект может реализовывать несколько интерфейсов событий.

## Подписка

```csharp
public sealed class CoinsView : MonoBehaviour, ICoinsChangedEvent
{
    private void OnEnable()
    {
        EventBus.Subscribe(this);
    }

    private void OnDisable()
    {
        EventBus.Unsubscribe(this);
    }

    public void OnCoinsChanged(int amount)
    {
        UpdateView(amount);
    }
}
```

`Subscribe()` автоматически находит все event-интерфейсы объекта. Повторная подписка
одного экземпляра не добавляет дубликат. Метод возвращает `true`, если объект был
добавлен хотя бы в один список:

```csharp
bool subscribed = EventBus.Subscribe(this);
bool unsubscribed = EventBus.Unsubscribe(this);
```

Компоненты на основе `PRMonoBehaviour` регистрируются в `EventBus` автоматически в рамках lifecycle SDK. Не добавляйте им дополнительную ручную подписку без необходимости.

## Публикация

```csharp
EventBus.RaiseEvent<ICoinsChangedEvent>(
    listener => listener.OnCoinsChanged(currentCoins));
```

Listeners вызываются в порядке подписки. Исключение одного listener логируется через
`Debug.LogException` и не останавливает вызов остальных.

Для публикации используется кэшируемый snapshot. Он перестраивается только после
изменения состава подписчиков, поэтому повторные события одного типа не создают новую
коллекцию при каждом вызове. Это особенно важно для `IOnUpdateEvent` и других
высокочастотных событий.

`RaiseEvent` не предназначен для получения результата или изменения дальнейшего поведения отправителя:

```csharp
// Не используйте EventBus как скрытый запрос разрешения.
EventBus.RaiseEvent<ICanBuyEvent>(listener => listener.Check(context));

// Для управляемого перехвата используйте HookSystem.
HookManager.Instance.Publish(context, BuyItem);
```

## Изменение подписок во время публикации

Публикация выполняется по snapshot списка. Поэтому добавленный во время callback
listener начнёт получать события со следующей публикации. Listener, удалённый во
время текущей публикации, может получить уже начатое событие, но гарантированно
отсутствует в следующем.

Вложенная публикация того же event-интерфейса поддерживается: каждый вызов использует
стабильный snapshot, а callbacks выполняются без удержания внутренней блокировки.

## Диагностика и очистка

В Play Mode вкладка `Events` окна `PRUnitySDK Debug` показывает последние 200 обычных публикаций:
event-интерфейс, локальное время вызова и число живых подписчиков. Покадровые
`IOnUpdateEvent` и `IOnPRUpdateEvent` агрегируются в отдельной таблице и не вытесняют полезные
события из истории. Для них отображаются количество вызовов, средняя частота, подписчики и
время последнего вызова. Захват работает только пока Debug-окно открыто и включён переключатель
`Capture`; историю можно временно остановить или очистить. Payload не сохраняется, поэтому
монитор не удерживает игровые объекты и event args.

В Editor монитор получает данные через `EventBus.OnEventRaised`. Этот диагностический event
компилируется только с `UNITY_EDITOR` и отсутствует в player build.

Количество живых подписчиков определённого интерфейса:

```csharp
int count = EventBus.GetSubscriberCount<ICoinsChangedEvent>();
```

Полная очистка:

```csharp
EventBus.Clear();
```

`Clear()` удаляет все глобальные подписки и предназначен для полного reset SDK, тестов или смены изолированного runtime-контекста. Не вызывайте его для очистки одного объекта.

Уничтоженные Unity-объекты автоматически пропускаются при публикации и удаляются при
следующем обслуживании списка. Для обычных C#-объектов по-прежнему необходим явный
`Unsubscribe()`.

## Ограничения

- Используйте `EventBus` с основного Unity-потока. Доступ к реестру и создание snapshot
  защищены блокировкой, но callbacks намеренно выполняются вне неё и обычно обращаются
  к Unity API.
- Система хранит сильные ссылки на listeners до `Unsubscribe()` или `Clear()`.
- Забытый `Unsubscribe()` удерживает обычный C#-объект в памяти.
- `EventBus` не гарантирует приоритеты. Если порядок является частью игровой логики, рассмотрите `HookSystem`.
