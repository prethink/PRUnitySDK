# Reflection

Список классов, которые SDK находит по контракту, — вместо перебора всех типов сборки при запуске.

## Зачем

Часть классов SDK подключает сам: находит всех, кто реализует интерфейс или помечен атрибутом, и создаёт.
Так регистрируются правила характеристик, фоновые задачи, источники резерва предметов, наборы клавиш ввода,
миграции сохранения, обработчики эффектов способностей.

Найти их можно только перебором всех типов сборки (`Assembly.GetTypes()`), а первый такой перебор заставляет
среду выполнения загрузить описание каждого типа. Сборка у проекта одна, типов в ней больше десяти тысяч.
На слабом телефоне первый перебор занимал около 1,5 с запуска — ради восемнадцати классов.

## Как устроено

| Что | Где |
| --- | --- |
| `ReflectionContractAttribute` | метка контракта: интерфейса, базового класса или атрибута, по которому классы ищутся |
| `ReflectionTypeRegistryGenerator` (Editor) | перед сборкой билда находит классы всех помеченных контрактов и пишет список |
| `Assets/PRUnityData/Resources/PRUnitySDK/ReflectionTypes.txt` | сам список; создаётся автоматически, править руками незачем |
| `ReflectionTypeRegistry` | читает список при запуске и отдаёт классы контракта по имени |

Перебор не исчез, он переехал в редактор: там он мгновенный (`TypeCache`). В билд едет готовый ответ,
и игра запрашивает у среды выполнения только перечисленные классы.

Формат файла — строка с `#` открывает контракт, под ней его классы:

```text
#IStatRuleProvider
PlayerRules, Assembly-CSharp
```

## Использование

Место, которое ищет классы, сначала спрашивает список и только при отказе перебирает сборку:

```csharp
Type[] candidates = ReflectionTypeRegistry.TryGetTypes(typeof(IStatRuleProvider), out IReadOnlyList<Type> listed)
    ? listed.ToArray()
    : typeof(IStatRuleProvider).Assembly.GetTypes();
```

В список попадают все неабстрактные и необобщённые классы контракта. Остальные условия — конструктор без
параметров, включён ли атрибут — вызывающий проверяет сам, как и после перебора.

Для интерфейсов есть готовый помощник: `ReflectionExtension.FindClassesImplementingInterface<T>()` уже
ходит через список.

## Новый контракт

Пометьте интерфейс, базовый класс или атрибут-метку:

```csharp
[ReflectionContract]
public interface IStatRuleProvider { }
```

Больше ничего не нужно: генератор найдёт помеченное сам, в том числе в коде проекта, о котором ядро не знает.
Классы контракта заодно попадают в `link.xml` — иначе сборщик мог бы вырезать класс, который игра
запрашивает по имени.

Добавлять сами классы можно как раньше: реализовал интерфейс или поставил атрибут — в билде он будет.

## Когда список не используется

`TryGetTypes` возвращает `false`, и место поиска делает прежний перебор, если:

- это редактор — там перебор быстрый, а новый класс должен работать в Play сразу, без пересборки списка;
- файла нет;
- контракта нет в файле (он не помечен `[ReflectionContract]`) — в лог уходит предупреждение;
- какое-то имя из файла не нашлось — список разошёлся с билдом, в лог уходит предупреждение.

То есть худший случай — прежняя скорость, а не пропавший класс. Отвечать наполовину список не станет:
если хоть одно имя не нашлось, весь контракт уходит на перебор.

## Ограничения

- **Новое место с перебором.** Код, который сам зовёт `Assembly.GetTypes()` при запуске и не спрашивает
  список, снова заплатит полную цену первого перебора. Ничего не сломается, запуск станет медленнее;
  в диагностике загрузчика (`BootstrapProbe`) это видно строкой в `slowest`.
- **Класс, который есть только в билде.** Список собирает редактор и видит только то, что скомпилировано
  в нём. Класс контракта внутри `#if !UNITY_EDITOR` в список не попадёт и в игре не найдётся. Сейчас таких
  классов нет; если понадобится — регистрируйте его явно.
- **Проверка в редакторе.** `ReflectionTypeRegistry.UseInEditor = true` включает список и в редакторе —
  для проверок; по умолчанию выключено.

Пересобрать список вручную: `PRUnitySDK → Обновить список типов`. Перед сборкой билда это делается само.
