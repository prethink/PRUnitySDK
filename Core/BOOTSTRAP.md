# Запуск SDK

Подробности того, что происходит между Play и первым кадром игры: экран загрузки, сборка SDK порциями,
затемнение на переходах, настройки запуска и диагностика загрузочной сцены. Как подготовить сцены —
в [README фреймворка](../README.md#1-подготовьте-bootstrap-сцену).

## Экран загрузки

Экран показывается с начала сборки SDK до первого кадра игровой сцены. Если он выключен,
SDK собирается одним вызовом, а сцена меняется через `SceneChanger` с затемнением.

На экране: подпись с пояснением, вращающийся значок и полоса прогресса. Первая половина полосы —
сборка SDK, дальше загрузка сцены, в конце её включение и первый кадр. До готовности SDK подписи
берутся по коду языка площадки, после — живые.

**Настройка.** Вид экрана лежит в настройках проекта (`PRUnitySDK.Settings.LoadingScreen`,
`LoadingScreenSettings`) и правится в окне `PRUnitySDK → Windows → Loading Screen`:

| Раздел | Что задаётся |
| --- | --- |
| Экран загрузки | показывать ли его вообще |
| Фон | цвет, картинка, способ вписать её в экран (растянуть, закрыть целиком, вписать), оттенок |
| Текст | шрифт; заголовок и пояснение на трёх языках, их цвет и размер, показывать ли каждый |
| Полоса прогресса | показывать ли, размер, цвета, картинки подложки и заполнения |
| Значок | показывать ли, картинка, размер, скорость вращения |

Язык, на котором свой текст не вписан, показывает стандартный (`LoadingScreenLabels`: «Загрузка...»
и «Подготавливаем игру. Это может занять несколько секунд.»), поэтому заполнять все три поля не обязательно.

Справа в окне — превью: тот же экран на выбранном языке и с выбранной долей прогресса.
Собирается методом `BootstrapLoadingScreen.Build` во временной сцене, открытую сцену не трогает.

Префаба нет: экран собирается кодом из настроек. Разметка (значок, заголовок, пояснение,
полоса — сверху вниз по центру) задана в коде под холст 1920×1080.

**Сборка SDK порциями.** С экраном загрузки `Bootstrap` проходит шаги `PRUnitySDK.InitializeSDKSteps`
порциями (по умолчанию 200 мс) и отдаёт кадр между ними. Порядок шагов тот же, что у
`PRUnitySDK.InitializeSDK()`. SDK становится готовым только на последнем шаге: до него общий цикл
обновления не идёт, а подписчики `ReadySignal` ничего не получают. Выключается и настраивается
в настройках проекта — см. ниже.

Между шагами проходят кадры: у уже созданного менеджера работает собственный `Update`, а события
площадки (фокус, пауза) могут прийти при полусобранном SDK. Код, которому нужен готовый SDK,
обязан ждать `ReadySignal`, а не рассчитывать, что соседи уже созданы.

**Значок в WebGL.** В WebGL значок рисует и крутит страница (`Plugins/WebGL/BootstrapSpinner.jslib`).
Экран отдаёт ей спрайт и его место, а свой значок прячет. Полоса и текст остаются в Unity
и замирают вместе с ней.

## Затемнение (ScreenFade)

`ScreenFade` закрывает экран на переходах: смену сцены через `SceneChanger` и любые переходы внутри сцены
(`ScreenFade.Instance.FadeIn(() => { …; ScreenFade.Instance.FadeOut(); })`). Вид — в настройках проекта
`SceneTransition → Fade` (`ScreenFadeSettings`), читается на каждом переходе:

| Поле | Что задаёт |
| --- | --- |
| `Mode` | `Fade` — плавное затемнение; `Iris` — «диафрагма» из мультфильмов: круг сжимается и раскрывается |
| `Duration` | секунды на закрытие и столько же на открытие |
| `Color`, `Image` | цвет шторки или картинка на весь экран (цвет её красит) |
| `Pattern`, `PatternColor`, `PatternTileSize`, `PatternSpeed` | плывущий узор поверх, как фон магазина; у текстуры Wrap Mode = Repeat |
| `IrisOnPlayer`, `IrisSoftness` | круг сходится на своём игроке (нет игрока — на центре экрана), мягкость кромки |
| `CloseSound`, `OpenSound` | звуки закрытия и открытия; готовые — `Core/#UI/ScreenFade/Sounds` |

Круг вырезает шейдер `PRUnitySDK/UI/ScreenFadeIris` (поле `irisShader` префаба `Resources/PRUnitySDK/Prefabs/ScreenFader`),
поэтому он режет и картинку, и узор. Без шейдера `Iris` работает как обычное затемнение и пишет предупреждение.
Время немасштабируемое: переход идёт и на паузе.

## Настройки запуска

Всё, что касается запуска, лежит в настройках проекта — `PRUnitySDK.Settings.Bootstrap`
(`BootstrapSettings`). На объектах загрузочной сцены настроек нет.

| Поле | По умолчанию | Что задаёт |
| --- | --- | --- |
| `Game Scene Index` | 1 | индекс игровой сцены в Build Settings |
| `Start From Editor Scene` | нет | только в редакторе: после Bootstrap открыть сцену, активную перед Play |
| `Spread Initialization` | да | собирать SDK порциями с кадрами между ними |
| `Frame Budget Seconds` | 0,2 | сколько секунд сборки идёт подряд, прежде чем отдать кадр |
| `Probe Enabled` | да | замерять стадии запуска (только в отладочном режиме проекта) |
| `Probe On Screen` | да | показывать цифры на экране, а не только в логе |
| `Probe Background Color` | синий | фон загрузочной сцены при включённой диагностике |
| `Probe Summary Seconds` | 20 | сколько держать итог в углу после загрузки |

`Start From Editor Scene` работает и для сохранённых сцен, отключённых в Build Settings
или не добавленных туда. Путь запоминается перед Play и сохраняется через перезагрузку домена.
Если открыта сама bootstrap-сцена или сцена ещё не сохранена, используется `Game Scene Index`,
а в Console появляется предупреждение. При нескольких открытых сценах запускается активная.
После выхода из Play Unity возвращает редакторный набор сцен.

## Площадка не ответила

С подключённой площадкой загрузчик начинает сборку SDK по её сигналу. SDK площадки может не ответить ни успехом,
ни ошибкой, поэтому ожидание ограничено: `Bootstrap → Platform Wait Seconds` в настройках проекта (20 с, ноль — ждать
без предела). Не дождался — игра запускается без площадки:

- `Bootstrap.StartedWithoutPlatform` — `true`, в журнале ошибка;
- сервисы площадки работают как без неё (каждый проверяет готовность своего SDK сам);
- хранилище площадки сохранение не читает и не пишет до конца запуска (`GameDataStorageBase.NeedsPlatform`): если
  площадка ответит позже, прогресс этого запуска не ляжет поверх настоящего;
- опоздавший сигнал площадки сборку SDK второй раз не начинает.

Игроку сейчас ничего не сообщается. Проверка — Play-тест «Запуск без ответа площадки» (`Modules/PlayTest`): он просит
загрузчик пропустить сигнал площадки (`Bootstrap.EditorSilentPlatform`) и ждать 3 с (`EditorPlatformWaitOverride`);
обе подмены одноразовые и только в редакторе.

## Диагностика загрузочной сцены

Загрузчик создаёт зонд `BootstrapProbe`, если он включён в настройках запуска и проект в отладочном
режиме. Ставить его на сцену не нужно:

- фон сцены становится цветным (`Background Color`): чёрный экран значит, что до сцены дело ещё не дошло;
- вверху пишется стадия загрузчика (`Bootstrap.Stage`), секунды в ней и счётчик кадров. Счётчик
  стоит — главный поток занят; идёт — игра ждёт чего-то снаружи;
- после загрузки игровой сцены в левом верхнем углу `Summary Seconds` секунд висит итог, он же
  уходит в лог с пометкой `[BootstrapProbe]`.

| Строка | Что в неё входит |
| --- | --- |
| `engine` | от запуска движка до первой сцены |
| `1 platform` | ожидание данных площадки; без площадки — ноль |
| `2 sdk` | сборка SDK: менеджеры, база, сохранение |
| `3 scene` | загрузка игровой сцены |
| `first frame` | от загрузки игровой сцены до её первого кадра |
| `engine frame 1 at` | когда движок отдал первый кадр: до этого на экране нет ничего от игры |
| `sdk steps N, work X, slowest:` | число шагов сборки SDK, их чистое время без отданных кадров и восемь самых долгих (`PRUnitySDK.InitializationSteps`) |

При сборке порциями стадия `2 sdk` длиннее строки `work`: в неё входят и кадры между порциями.

`Bootstrap` сам записывает время стадий в момент перехода (`Bootstrap.StageStartTimes`).

Это инструмент проверки, а не экран загрузки: текст служебный и не переводится. Работает он только
в отладочном режиме проекта — `PRUnitySDK.Settings.Project.IsDebug`, то есть `Release Type = Debug`
в настройках проекта. В релизном режиме зонда нет вовсе: ни надписей, ни лога.
Перед выпуском достаточно переключить `Release Type`.
