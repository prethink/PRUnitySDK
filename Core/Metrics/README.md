# Metrics

`PRUnitySDK.Metric` выбирает адаптер при инициализации SDK. `MetricBase` поддерживает
событие без параметров и дерево параметров; перегрузки со строковым словарём и
путём из трёх строк сводятся к дереву. `YGMetrics` нормализует значения для YGPlugin,
`DummyMetric` намеренно ничего не отправляет.

## Одна ветка на событие

Отчёт Яндекс Метрики по параметрам строит дерево только из ключей JSON: имени цели в нём нет,
а ключи одного уровня становятся несвязанными узлами. Поэтому параметры события отправляют
одной веткой, которая начинается с его имени:

```csharp
PRUnitySDK.Metric?.SendBranch("shop_buy", offer.DatabaseCategory, MetricKeys.Item(item));
// shop_buy → HatDefinition → Chef's hat-864d4ae5-…
```

`SendBranch` сам ставит имя события корнем и не пробрасывает сбой отправки. `MetricKeys` даёт
подписи в одном формате «название-идентификатор»: `Item` — предмет, `Reward` — награда
(у ресурса дописано количество: `Coin x30`; у контейнера названием служит имя ассета).
Название служебное (`Name`), не перевод.

Вызов из трёх строк `Send("emote", "play", key)` — та же ветка: `emote → play → key`.
Словарь с несколькими ключами (`Send(name, Dictionary)`) уходит как есть, без корня.

## Журнал Editor

В `PRUnitySDK/Windows/Debug Window` есть вкладка `Metrics`. Она показывает последние
200 вызовов: время UTC, событие, адаптер, JSON параметров. Поиск ищет также внутри
JSON; `Copy` копирует запись целиком. `Capture` включает запись, `Clear` очищает
историю без изменения отправки метрик.

Журнал собирается с начала запуска независимо от открытого окна. После остановки
он доступен в Edit Mode, при новом Play Mode очищается, в том числе без domain reload.
Перекомпиляция с перезагрузкой домена тоже очищает статическую историю.
`Sent` означает завершённый вызов адаптера, `Ignored` — пропуск, например в
`DummyMetric`. API не получает подтверждения доставки сервером.

`YGMetrics` записывает нормализованное дерево, которое передаёт плагину:
пропущенные значения в журнал не возвращаются. JSON снимается при вызове;
последующая правка исходного словаря или списка не меняет историю.

Для собственного адаптера вызовите `ReportSend` после его успешной отправки:

```csharp
public override void Send(string eventName, IReadOnlyDictionary<string, object> parameters)
{
    SendToPlatform(eventName, parameters);
    ReportSend(eventName, parameters);
}
```

При намеренном пропуске используйте `ignored: true`.
Каждый вызов записывается в конечной перегрузке, поэтому вспомогательные перегрузки
не создают дубликатов. Исключение при отправке не записывается как успех.
Если невозможно снять параметры, в записи остаётся ошибка сериализации,
а успешная отправка не ломается из-за диагностики.

`MetricDebugHistory` и `MetricDebugEntry` существуют только под `UNITY_EDITOR`.
`ReportSend` помечен `Conditional("UNITY_EDITOR")`: в player-сборке его вызовы
исключены компилятором.
