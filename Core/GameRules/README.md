# GameRules

`GameRules` — глобальные ограничения характеристик. Это последний этап расчёта стата:
после того как применены базовые значения сущности и персональные модификаторы,
правила приводят результат в допустимые границы.

```text
EntityStatsBase → персональные модификаторы → GameRules → итоговое значение
```

Правила применяются ко всем сущностям одинаково, но **свои у каждого проекта SDK**: они лежат
в настройках проекта (`PRSDKSettings` → раздел `StatRules`). В одном Unity живёт несколько игр,
и правила одной на другую не накладываются.

## Правило и модификатор — не одно и то же

Эту границу проще всего перепутать, поэтому она проговорена явно.

| | Модификатор | Правило |
| --- | --- | --- |
| Кому принадлежит | конкретной сущности | проекту (игре) |
| Откуда берётся | шляпа, питомец, бафф, экипировка | настройки проекта, окно `Game Rules` |
| Что выражает | «этот игрок быстрее на 20%» | «скорость не бывает меньше 0.2» |
| Когда меняется | в рантайме, постоянно | при старте SDK (в редакторе — и при правке в окне во время игры) |
| Что происходит при конфликте | складываются или перемножаются | значение обрезается |
| Где живёт | `PropertyContainer` и сборщик модификаторов проекта | `GameRules` |

Практический критерий: если значение сломает игру или систему — это правило.
Если оно просто делает персонажа сильнее или слабее — это модификатор.
Например, `Min(WalkSpeed, 0.2)` нужен, потому что при нулевой скорости ломается контроллер.

## Состав

| Тип | Назначение |
| --- | --- |
| `GameRules` | Статический реестр: при старте берёт правила из настроек активного проекта и применяет их |
| `GameRulesSettings` | Раздел настроек проекта: список правил (`PRSDKSettings.StatRules`) |
| `StatRuleBase` | Базовое правило: характеристика, приоритет, метод `Apply` |
| `MinValueRule` | Нижняя граница значения |
| `MaxValueRule` | Верхняя граница значения |
| `StatKeyAttribute` | Строковое поле характеристики с выпадающим списком в инспекторе |
| `GameRulesWindow` | Окно `PRUnitySDK/Windows/Game Rules` (редактор) |

## Как задать правила

Окно **PRUnitySDK → Windows → Game Rules** правит правила **активного** проекта (переключение — в окне `Project`):

- «Добавить правило» — выбор типа (Min Value Rule, Max Value Rule и свои наследники `StatRuleBase`);
- в строке — характеристика из списка, граница, приоритет; стрелки меняют порядок, крестик удаляет;
- сверху предупреждения: правило без характеристики, минимум выше максимума у одной характеристики;
- внизу «Проверка значения» — что вернут правила для введённого числа, без запуска игры.

Список характеристик собирается из наборов, на которых построены ассеты статов (`EntityStatsBase<T>`, например
`PlayerStats` → `PlayerStatsEnumeration`). Характеристика хранится строкой: если её переименовать в коде, в окне она
станет `Missing: старое имя` и перестанет применяться — выберите новую.

Тот же список виден и в общем окне настроек (`PRUnitySDK/Windows/Settings`, раздел `Stat Rules`).

Во время игры правка в окне сразу перезагружает правила. Правка того же раздела через окно настроек или инспектор
применится со следующего запуска.

## Применение

```csharp
float speed = GameRules.ApplyStatRules(PlayerStatsEnumeration.WalkSpeed, rawSpeed);
int    count = GameRules.ApplyIntStatRule(PlayerStatsEnumeration.MaxJumpCount, rawCount);
long   value = GameRules.ApplyLongStatRule(SomeStat, rawValue);
```

В обычном коде вызывать это напрямую не нужно — правила уже применяются внутри:

- `EntityStatsUtils.GetStat()` / `GetStatInt()` / `GetStatLong()`;
- `PropertyContainerBase.GetWithRules()`.

Повторно применять правила поверх результата этих методов не нужно и вредно.

Если для стата не задано ни одного правила (или передан `null`), значение возвращается
без изменений.

`GameRules.Initialize()` вызывается из `PRUnitySDK.InitializeSDK` первым шагом. Пустой элемент списка и правило
без характеристики пишутся в лог и пропускаются; SDK не падает. Для тестов есть `GameRules.Initialize(rules)` —
загрузить свой набор вместо настроек.

## Порядок применения

Правила одной характеристики применяются по возрастанию `Priority` — меньшее значение
раньше, как у `MethodHookAttribute.Order`. По умолчанию `100`. Правила с равным
приоритетом сохраняют порядок в списке настроек.

Для пары Min и Max порядок не важен: при `min <= max` результат одинаков. Он важен для некоммутативных правил:
умножения, округления, кривой.

## Диагностика

```csharp
bool ready = GameRules.IsInitialized;      // правила загружены
int total  = GameRules.RuleCount;          // сколько всего загружено
var stats  = GameRules.Stats;              // какие характеристики затронуты

foreach (StatRuleBase rule in GameRules.GetRules(PlayerStatsEnumeration.WalkSpeed))
    Debug.Log($"{rule.GetType().Name} priority={rule.Priority}");
```

`GetRules()` возвращает правила в порядке применения.

Во время игры вкладка `Rules` окна `PRUnitySDKDebug` показывает загруженные правила и даёт прогнать через них
число. См. [Editor](../Editor/README.md).

## Новый тип правила

Правила лежат в настройках списком `[SerializeReference]`, поэтому у типа должны быть `[Serializable]`, конструктор
без параметров и поля с `[SerializeField]` — свойства не сохраняются. Новый тип сам появится в меню «Добавить правило».

```csharp
[Serializable]
public class StepRule : StatRuleBase
{
    [SerializeField] private float step = 1f;

    public StepRule()
    {
    }

    public StepRule(Enumeration stat, float step, int priority = DefaultPriority)
        : base(stat, priority)
    {
        this.step = step;
    }

    public override float Apply(float value)
    {
        return step > 0f ? Mathf.Round(value / step) * step : value;
    }
}
```

Переименование или перенос класса правила ломает уже сохранённые элементы (Unity хранит имя типа) — используйте
`[UnityEngine.Scripting.APIUpdating.MovedFrom]`. Если операция правила некоммутативна, задайте приоритет явно.

## Ограничения

- **Противоречивые правила только подсвечиваются.** Окно предупреждает, если минимум выше максимума; в игре
  результат тогда зависит от порядка, SDK его не исправляет.
- **Отсечение ничем не отмечается.** Бафф может не дать эффекта, потому что значение уже упёрлось в потолок,
  и никто этого не узнает: срабатывание клампа в рантайме не логируется.
- **Набор фиксируется на сеанс.** Правила, зависящие от состояния игры или настроек игрока, так задать нельзя.
- **Правила проектные, а не сущностные.** Границ уровня «для этого режима» или «для этой сущности» нет.
- **Только `float`.** `ApplyIntStatRule` и `ApplyLongStatRule` — это округление результата, а не отдельная точность.
