# Локализация

Модуль выводит переведённые тексты и обновляет их при смене языка. Перевод в SDK хранится не в одном файле, а рядом с тем, к чему относится:

| Где | Что там | Кто читает |
| --- | --- | --- |
| `LocalizationDatabase.Common` и `.Project` | общие подписи по ключу | `L.Tr(key)`, `LocalizationKeyObserver`, `LocalizationObserver.globalKey` |
| Ассеты предметов, наград, достижений | название и описание конкретной вещи | `item.GetName()`, `reward.GetTranslate()` |
| Компоненты на префабах | подписи интерфейса, которых нет в общем списке | `LocalizationObserver.localization` |

Этот способ неудобен, когда нужно охватить всё сразу: добавить язык, отдать тексты на перевод, найти пустые строки.

## Как вывести переведённый текст

Строка не присваивается в `text` — вместо неё тексту отдают источник перевода:

```csharp
title.SetLocalization(ShopLabels.Title, new[] { count.ToString() });
label.SetLocalizationKey("shop_buy_button");
name.SetLocalization(itemDefinition);
```

Присвоенная строка застывает на языке, который был при отрисовке, и меняется только при пересборке окна. `SetLocalization` вешает на текст `LocalizationObserver`: он подписан на смену языка и перерисовывает подпись сам, в том числе в уже открытом окне.

Источник задаётся одним из способов:

| Источник | Когда | Как получить |
| --- | --- | --- |
| ключ в базе | строку правит дизайнер без пересборки | `SetLocalizationKey(key, args)` |
| ассет вещи | название предмета, награды, достижения | передать сам ассет: он уже провайдер |
| провайдер из кода | подписи интерфейса на трёх языках | `new LocalizationProvider(key, dictionary)` |
| одно число | счётчик, количество — подпись из числа и ничего больше | `SetLocalizedNumber(value)` |

У `SetLocalization` есть перегрузка с аргументами-функцией
(`SetLocalization(provider, () => new[] { ... })`). Она нужна, когда сам аргумент зависит
от языка — подробности в разделе [Числа тоже переводятся](#числа-тоже-переводятся).

Подписи модуля удобно собирать в один статический класс рядом с ним: по свойству на подпись, каждое отдаёт готовый провайдер.

### Подстановка значений

Число или имя подставляются аргументами, а перевод пишется форматом целиком:

```csharp
info.SetLocalization(ShopLabels.PriceWithDiscount, new[] { price, discount });
```

Перевод — `"Цена: {0}\nСкидка: {1}"`. Склеивать текст из кусков в коде нельзя: порядок частей и перенос строки в разных языках разные. Если аргументы не совпадут с форматом, наблюдатель не упадёт: покажет перевод без подстановки и запишет в лог ключ, который виноват.

Когда изменилось не язык, а подставляемое значение, достаточно `Refresh()` у наблюдателя.

### О чём легко забыть

Название вещи не берут из `Name`: это служебный идентификатор. Ассеты предметов, наград и достижений сами реализуют `ILocalizationProvider`, и спрашивают перевод у них.

Словарь у ассета бывает пуст. Тогда `GetTranslate()` вернёт не пустую строку, а пометку `NotFoundTranslate`, и она попадёт игроку на экран. Там, где ассет заполняет не программист, стоит предусмотреть запасной вариант: проверить словарь и при пустом отдать `new LocalizationProvider(item.Name)`.

Ссылку на свой `TextMeshProUGUI` проставляет `GetLanguageComponent`, то есть любой вызов `SetLocalization`. На префабе её проставляет `OnValidate`, но в собранной игре он не вызывается. Если наблюдатель добавляют вручную через `AddComponent`, поле нужно заполнить самому.

## Два наблюдателя

Наблюдатель за языком — два компонента с общей базой `LocalizationObserverBase`: подписка на смену языка, аргументы подстановки и перерисовка текста у них одинаковые, различается только источник строки.

| Компонент | Источник | Когда брать |
| --- | --- | --- |
| `LocalizationObserver` | провайдер, ассет или ключ в базе | подпись приходит из кода: название предмета, строка из класса подписей |
| `LocalizationKeyObserver` | только ключ в базе | подпись лежит в базе и правится дизайнером |

У `LocalizationObserver` есть свой словарь (`localization`). Перевод из него не попадает в общий список: чтобы отдать такую строку на перевод или добавить язык, нужно обходить префабы. `LocalizationKeyObserver` хранит на объекте только ключ, а перевод живёт в базе и виден в окне локализации целиком.

Кодом вешается `LocalizationObserver`: это делают `SetLocalization` и `SetLocalizationKey`. `LocalizationKeyObserver` ставят руками на префаб.

Двух наблюдателей на одном тексте быть не должно: оба пишут в тот же `TextMeshProUGUI`, и на экран попадёт тот, кто отработал последним. Ошибки при этом нет, поэтому при готовности SDK наблюдатель проверяет соседей сам и пишет предупреждение в лог.

## Числа тоже переводятся

Сокращённое число содержит слово разряда, и оно зависит от языка: в английском `B` — billion, в турецком `bin` — тысяча.

Подписи разрядов лежат в базе под ключами `number_suffix_k`, `_m`, `_b`, `_t` (группа `number`). Ключи `_p`, `_e`, `_z`, `_y`, `_r` пока не заведены. Если ключа нет, остаётся латинская буква: числа не ломаются ни до загрузки базы, ни без переводов. `NumberConverter` берёт подписи у поставщика `INumberSuffixProvider`; ставит поставщика модуль локализации при инициализации.

Из этого следует правило для кода: **число, попадающее в подпись, отдают функцией**.

```csharp
progressText.SetLocalization(XPBarLabels.Progress,
    () => new[] { NumberConverter.FormatNumber(current), NumberConverter.FormatNumber(total) });

countText.SetLocalizedNumber(count);   // подпись состоит из одного числа
```

Готовая строка застывает на языке момента вызова, и в открытом окне после смены языка остался бы старый разряд. Функцию наблюдатель вызывает заново при каждой смене языка, поэтому она должна быть дешёвой и ничего вокруг не менять.

`SetLocalizedNumber` — для подписей из одного числа: счётчик в ячейке хотбара, количество в списке. Число, присвоенное в `text`, выглядит непереводимым, но его разряд — тоже слово.

## Окно переводов

`PRUnitySDK/Windows/Localization` — одно окно на все переводы, три вкладки:

| Вкладка | Что правится |
| --- | --- |
| `Common` | общий список SDK: ключ и значения по языкам |
| `Project` | общий список игры, устроен так же |
| `Проект` | всё остальное: словари ассетов и подписи на префабах |

Поиск общий для всех вкладок: набранное в строке сверху фильтрует и списки базы, и собранную таблицу. Первые две вкладки требуют базу SDK, третья работает и без неё: переводы предметов и подписи окон лежат в своих ассетах.

### Группы

Записи в списках раскладываются по группам и сворачиваются: подписи качества отдельно от подписей магазина. Группа — поле записи, но заполнять его вручную обычно не нужно: если оно пустое, группа берётся из префикса ключа (`quality_rare` → `quality`, `shop.buy` → `shop`). Кнопка **Группы из ключей** проставляет их разом по обоим спискам и не трогает те, что заданы руками.

Группа не влияет на поиск перевода в игре: он по-прежнему ищется по ключу. Порядок записей в списке она тоже не меняет.

Группа ездит вместе с переводом: в CSV для неё есть колонка `Group`, и импорт возвращает её на место. Заполнена она там, где есть в данных: у записей общего списка и у подписей на префабах (они используют `LocalizationControl`). У предметов словарь лежит без обёртки, колонка пустая: такой перевод и так виден по владельцу.

### Перенос между списками

Кнопка `→ Project` (или `→ Common`) переносит запись со всеми переводами в соседний список и удаляет исходную. Если ключ там уже есть, окно спрашивает, заменить ли его: один ключ в двух списках дал бы два разных перевода.

### Вкладка «Проект»

Собирает переводы по всему проекту и обменивается ими через CSV.

**Собрать** — обход указанных папок: ScriptableObject-ассеты и, если включено, префабы со всеми компонентами. Ищется форма данных, а не имя поля: словарь, где ключи — языки, а значения — строки. Так находится и тип, который инструмент не знает, если у него есть такой словарь.

**Экспорт CSV** — выгружает то, что видно с учётом фильтров. Колонки: адрес, ключ, группа, источник, владелец и по колонке на язык. Разделитель — точка с запятой, файл с BOM: так таблица открывается в Excel сразу, кириллица не портится.

**Импорт CSV** — возвращает значения на место. Место определяется адресом строки (`ассет|объект|свойство`), а не ключом: у предметов ключ вычисляется из имени и в данных не хранится. Если языка в словаре не было, он добавляется, но только при непустом переводе: пустая строка язык не добавляет.

Фильтры помогают выделить работу: источник (база, ассеты, префабы), поиск по тексту и «только неполные» — строки, где заполнены не все языки.

## Зависимости

| От чего зависит | Зачем |
| --- | --- |
| `PRSDKDatabase` | общий список переводов и язык по умолчанию |
| `LanguageManager` | текущий язык и событие его смены |
| TextMeshPro | `LocalizationObserver` подписывает текст на смену языка |
| `NumberConverter` | сокращает числа; подписи разрядов берёт у этого модуля |
| Сериализуемый словарь | хранение значений по языкам в ассетах |

Кто зависит от неё: почти всё, что показывает текст, — предметы, награды, окна. Локализация о них не знает: перевод либо лежит в самом объекте, либо ищется по ключу.

## Чего инструмент не делает

- Не создаёт новые ключи в общем списке: для этого есть соседние вкладки `Common` и `Project`.
- Не видит подписи, собранные в коде (наборы провайдеров в статических классах). Чтобы строка попала в таблицу, её переносят в базу и подключают по ключу.
- Импорт нельзя отменить: значения пишутся сразу в ассеты, и вернуть их можно только системой контроля версий. Поэтому импорт спрашивает подтверждение.

## Как добавить язык

1. Добавить значение в `LangType`.
2. Собрать таблицу и выгрузить CSV.
3. Заполнить новую колонку и загрузить файл обратно.
4. Проверить фильтром «только неполные», что не осталось пустых строк.
