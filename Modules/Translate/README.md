# Локализация

Перевод в SDK хранится не в одном файле, а рядом с тем, к чему относится:

| Где | Что там | Кто читает |
| --- | --- | --- |
| `LocalizationDatabase.Common` и `.Project` | общие подписи по ключу | `L.Tr(key)`, `LocalizationObserver.globalKey` |
| Ассеты предметов, наград, достижений | название и описание конкретной вещи | `item.GetName()`, `reward.GetTranslate()` |
| Компоненты на префабах | подписи интерфейса, которых нет в общем списке | `LocalizationObserver.localization` |

Такое хранение удобно правкой: перевод лежит там же, где вещь, и не разъезжается
с ней при переносе. Неудобно оно ровно в одном случае — когда нужно охватить всё сразу:
добавить язык, отдать тексты на перевод, найти пустые строки.

## Окно переводов

`PRUnitySDK/Tools/Localization` — одно окно на все переводы, три вкладки:

| Вкладка | Что правится |
| --- | --- |
| `Common` | общий список SDK: ключ и значения по языкам |
| `Project` | общий список игры, устроен так же |
| `Проект` | всё остальное: словари ассетов и подписи на префабах |

Поиск общий для всех вкладок: набранное в строке сверху фильтрует и списки базы,
и собранную таблицу. Первые две вкладки требуют базу SDK, третья работает и без неё —
переводы предметов и подписи окон лежат в своих ассетах.

### Группы

Записи в списках раскладываются по группам и сворачиваются: подписи качества отдельно
от подписей магазина. Группа — поле записи, но заполнять его вручную обычно не нужно:
если оно пустое, группа берётся из префикса ключа (`quality_rare` → `quality`,
`shop.buy` → `shop`). Кнопка **Группы из ключей** проставляет их разом по обоим спискам
и не трогает те, что заданы руками, — ручная правка точнее догадки по имени.

На поиск подписи в игре группа не влияет: перевод по-прежнему ищется по ключу. Порядок
записей в списке она тоже не меняет — иначе перестановка ради вида плодила бы правки
в ассете базы.

Группа ездит вместе с переводом: в CSV для неё есть колонка `Group`, и импорт кладёт
её обратно. Заполняется она там, где хранится в данных — у записей общего списка
и у подписей на префабах (те тоже используют `LocalizationControl`). У предметов
словарь лежит без обёртки: колонка для них пустая, и группировать там нечего —
такой перевод и так виден по владельцу.

### Перенос между списками

Кнопка `→ Project` (или `→ Common`) переносит запись со всеми переводами в соседний
список и удаляет исходную. Если ключ там уже есть, окно спрашивает, заменить ли его:
один ключ в двух списках означал бы два разных перевода, а игрок увидел бы тот, что
победит по порядку поиска.

### Вкладка «Проект»

Собирает переводы по всему проекту и обменивается ими через CSV.

**Собрать** — обход указанных папок: ScriptableObject-ассеты и, если включено, префабы
со всеми компонентами. Ищется не имя поля, а форма данных: словарь, ключами которого
служат языки, а значениями строки. Поэтому находится и тот тип, о котором инструмент
ничего не знает, — достаточно, чтобы у него был такой словарь.

**Экспорт CSV** — выгружает то, что видно с учётом фильтров. Колонки: адрес, ключ,
группа, источник, владелец и по колонке на язык. Разделитель — точка с запятой, файл с BOM:
так таблица открывается в Excel сразу и не портит кириллицу.

**Импорт CSV** — возвращает значения на место. Место определяется адресом строки
(`ассет|объект|свойство`), а не ключом: у предметов ключ вычисляется из имени и в данных
не хранится, так что опираться на него нельзя. Языка, которого в словаре не было,
добавится запись — но только если перевод непустой: пустая строка не должна заводить
язык, который никто не переводил.

Фильтры помогают выделить работу: источник (база, ассеты, префабы), поиск по тексту
и «только неполные» — строки, где заполнены не все языки.

## Зависимости

| От чего зависит | Зачем |
| --- | --- |
| `PRSDKDatabase` | общий список переводов и язык по умолчанию |
| `LanguageManager` | текущий язык и событие его смены |
| TextMeshPro | `LocalizationObserver` подписывает текст на смену языка |
| Сериализуемый словарь | хранение значений по языкам в ассетах |

Кто зависит от неё: почти всё, что показывает текст, — предметы, награды, окна.
Локализация о них не знает: перевод либо лежит в самом объекте, либо ищется по ключу.


## Чего инструмент не делает

- Не создаёт новые ключи в общем списке: для этого есть соседние вкладки `Common` и `Project`.
- Не трогает подписи, зашитые в коде окон (`WindowLabels` и подобные switch по языку) —
  их в данных нет.
- Не отменяет импорт: значения пишутся сразу в ассеты, и вернуть их можно только
  системой контроля версий. Поэтому импорт спрашивает подтверждение.

## Как добавить язык

1. Добавить значение в `LangType`.
2. Собрать таблицу и выгрузить CSV.
3. Заполнить новую колонку и загрузить файл обратно.
4. Проверить фильтром «только неполные», что не осталось пустых строк.
